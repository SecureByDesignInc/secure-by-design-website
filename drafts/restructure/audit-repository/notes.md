## Design decisions others build on

- **Identities:** `SBD-Archive$` (gMSA, retrievable only by SBD-SYSLOG01) creates files only. `SBD-Catalog$` and `SBD-Retention$` (gMSAs, retrievable only by SBD-AUDIT01) hash, and delete. `SBD Auditors` read through Remote Management Users from SBD-ADMIN-SRV01. `SBD Audit Custodians` are SBD-AUDIT01's local Administrators in place of Domain Admins.
- **Paths:** share `\\SBD-AUDIT01\LogArchive` (D:\LogArchive) with ForwardedEvents, Syslog, Catalog, and Retention folders. The share has `EncryptData $true` and ChangeAccess for SBD-Archive$ only. TCP 445 inbound is scoped to 10.0.20.20.
- **Permissions:** inheritance removed; SYSTEM F; RX for custodians, auditors, and the two AUDIT01 gMSAs. `OWNER RIGHTS (S-1-3-4):(OI)(IO)(RC)`. SBD-Archive$ `(WD,RA,S)` on each stream folder. SBD-Retention$ `(OI)(IO)(DE)`.
- **Tasks:** 'SBD Archive to AUDIT01' runs on SBD-SYSLOG01 daily at 01:00. The catalog task runs hourly, verification runs daily, and 'SBD Repository Retention' has no trigger. All run as gMSAs (`-LogonType Password`).
- **Events:** source `SBD-Repository` in the Application log writes 1000/1001 (arrival hash ok/mismatch) and 1100/1101 (daily verification ok/failed).
- **Evidence folder:** `C:\Evidence\audit-repository`.

- Facts checked: KDS root key wait of up to 10 hours, one per forest. SMB encryption: RejectUnencryptedAccess defaults to true, and SMB 1 must be off. Owner Rights SID S-1-3-4. The icacls codes WD/RA/S/DE/RC and (OI)(IO). File System auditing needs SACLs, Detailed File Share writes 5145, and 4656 is the failure event. Get-FileHash defaults to SHA256. gMSAs are supported for scheduled tasks, and New-ScheduledTaskPrincipal takes the LogonType values.

## Unsure

- **gMSA scheduled tasks:** the documented, widely used method is `New-ScheduledTaskPrincipal -UserId 'SBD\SBD-Archive$' -LogonType Password` with no password. Microsoft Learn confirms gMSAs support Task Scheduler and lists the LogonType values, but no Learn page shows this exact command. It is correct in practice; the source cited is the cmdlet page.
- **Create-without-delete:** the writer's file-creation behaviour is NTFS's documented rule (access requested at create time is granted; afterwards, the inherited DACL applies). The copy tool must not try to set attributes or timestamps after closing the file. With only WD/RA/S on the folder, `Copy-Item` can still fail on some metadata calls. If it does, add WA (write attributes) on files only. Worth testing in a lab before publishing.
- **Archive-day choice:** daily exports by TimeCreated (completed UTC days). Late events from a silent source are picked up with an `-r1` re-export after a gap. I didn't use an EventRecordID high-water mark: as far as I know, forwarded events keep their source's record IDs, so ForwardedEvents has no single arrival-ordered counter. Check this in a lab before choosing between the two.
- **AU-9(5) dual authorization** is used in lesson 4's text (not as a guide control card). Its title in NIST is "Protection of Audit Information | Dual Authorization", and the guide cards use only AU-4, AU-9, SI-7, AU-11. SI-7's title is taken from Inside the Network (architecture.js).
- The SCC "installer arrives over PowerShell remoting (Copy-Item -ToSession)" assumes the custodian's seat holds the staged SCC media from course 1.4; adjust if course 1.8 moved the tools only to AdminJumpBox01 (Tier 0), which can't manage SBD-AUDIT01.
