# Course guide content: what to write

Repository: /home/claude/secure-by-design-website (Secure By Design website). Work only in this clone. Do not commit, push, or edit any file other than the one JSON file you are assigned.

## Background

Course 1.1's interactive guide (public/training/dc01-dc02/index.html) has a chapter sidebar, three tabs per lesson (Walkthrough, Security reasoning, My evidence), and a 3D "lesson network" beside the lesson. Courses 1.2–1.10 are getting guides in the same design, generated by scripts/prepare-course-guides.mjs from:

- content/configuration-courses.json — the existing lesson content (summary, objectives, steps, command, check, evidence, quizzes, recap, next, sources, optional model link). This is the source of truth. Do NOT change it.
- content/videos.json → `courses[]` — course title, number, description, systems, stages.
- content/course-guides/<id>.json — the NEW guide-only content you write (schema below).

Read first: AGENTS.md (the latest dated sections win, especially the October 8–9 notes on the library restructure, DNS moving to course 1.2, SBD-TIME01 removed — the domain controller SBD-DC01, the PDC emulator, is the NTP source — and Inside the Network decisions), EDITORIAL_STYLE.md, content/inside-the-network.json (system names, roles, VLANs, addresses — the only source for names/addresses), and your course's entries in content/configuration-courses.json and content/videos.json. Look at the course 1.1 examples at the bottom of this file for tone and length.

Rules:
- Never contradict the lesson content. Everything you write must follow from what the course's lessons already say, plus content/inside-the-network.json.
- Never invent systems, hostnames, addresses, VLANs, products, or vendor hardware. Keep hardware vendor agnostic. Do not add NPS/RADIUS servers, network sensors or TIME01. Splunk, Nessus and ePO are single instances; Splunk and Nessus run on domain-joined Linux. The network core is a learner-built virtual layer 3 router ("the core"); don't name a make or model.
- NIST SP 800-53 Rev. 5 control IDs and their EXACT official titles (e.g. "SC-20" → "Secure Name/Address Resolution Service (Authoritative Source)", "CM-6" → "Configuration Settings", "AU-9" → "Protection of Audit Information"). Prefer controls the course content or content/inside-the-network.json already cites. If you use an enhancement, write it as "IA-2(1)" and give NIST's "Base | Enhancement" title form, e.g. "Identification and Authentication (Organizational Users) | Multi-factor Authentication to Privileged Accounts". If you are not certain of an exact title, pick a control whose title you are certain of. You may verify titles at https://csrc.nist.gov (WebFetch) if needed.
- Plain, direct, welcoming teaching voice; sentence case; no marketing fluff; no "I/we" for the brand except checklist items, which are the learner's first-person observations ("I recorded…").
- Use the Unicode characters the existing content uses (· → – ’) consistently. Valid JSON, 2-space indent, UTF-8.

## Schema: content/course-guides/<id>.json

```json
{
  "id": "<course id>",
  "hero": {
    "title": "First part of the course title",
    "accent": "rest of the course title.",
    "text": "One or two sentences in the style of 1.1's hero: what you build and on which systems, then 'Follow the build, explore the dependencies, and keep the evidence.' (or a close variant fitting the course). ≤ 400 chars."
  },
  "book": ["WINDOWS", "SERVER", "", "DNS + TIME"],
  "sample": [["Domain", "sbd.test"], ["SBD-DC01", "10.0.10.10 / 24"]],
  "scene": {
    "tag": "DOMAIN CONTROLLERS · VLAN 10",
    "label": "Interactive 3D lesson network showing … (one sentence for screen readers)",
    "completeStatus": "COURSE TARGET",
    "completeCaption": "One or two sentences: what the finished course leaves in place.",
    "nodes": [
      {
        "id": "dc1",
        "name": "SBD-DC01",
        "sub": "10.0.10.10",
        "kind": "server",
        "row": "back",
        "existing": true,
        "from": 0,
        "button": "SBD-DC01",
        "title": "SBD-DC01 · 10.0.10.10",
        "description": "1–3 sentences: this system's job in THIS course."
      }
    ],
    "flows": [
      { "from": "dc1", "to": "dc2", "lessons": [1, 2, 3], "label": "Zone replication", "twoWay": true }
    ]
  },
  "lessons": {
    "<lesson id>": {
      "short": "Sidebar label, ≤ 28 chars",
      "tag": "01 / PLAN",
      "status": "STAGE STATUS, ≤ 40 chars",
      "stepTitles": ["One heading per step, same order and count as the lesson's steps"],
      "mistake": "A realistic common mistake for this lesson and its consequence (1–3 sentences).",
      "network": "Caption for the 3D view at this lesson: which systems are live, what flows are shown, on which segments (1–2 sentences).",
      "control": {
        "id": "SC-20",
        "name": "Exact NIST SP 800-53 Rev. 5 title",
        "phase": "Implement → Assess",
        "body": "How this lesson implements or supports the control (1–3 sentences).",
        "question": "A reflective question for the learner."
      },
      "checklist": ["I …", "I …", "I …"]
    }
  }
}
```

Field rules (the generator enforces these):
- `hero.title` + " " + `hero.accent` reads as the course title from content/videos.json; the accent is its last few words and ends with a period (1.1: "Promote Primary & Secondary" + "Domain Controller.").
- `book`: up to 4 short UPPERCASE lines (≤ 14 chars each) for the workbook spine label; an empty string makes a spacer line. 1.1 uses ["WINDOWS", "SERVER", "", "DC01 + DC02"].
- `sample`: 4–7 rows of the sample values lesson 1 relies on (names, addresses/subnets, VLAN, domain), all taken from the course content or content/inside-the-network.json. Shown as a table at the top of lesson 1.
- `scene.nodes`: 2–7 nodes, at most 5 with row "back" and at most 5 with row "front". Back row sits behind the core switch, front row in front of it (use front for administration hosts, workstations, viewpoints). The first node is selected by default.
  - `kind`: "server" (rack server model), "offline" (server not cabled to the switch, amber — only for SBD-ROOTCA01), "workstation" (one desktop: admin hosts, jump boxes), "fleet" (three desktops — only for "50 Windows PCs"), "viewpoint" (a desktop labelled as where checks are run from; 1.1 used one for "Health checks · administration viewpoint").
  - `existing: true` when an earlier course built the system and it is already running at lesson 1; `from: <0-based lesson index>` when THIS course configures it (it lights up from that lesson). A node may have both (e.g. DCs exist, and DNS is configured on them in lesson 0). Every node needs at least one of the two.
  - `name` ≤ 80 chars (shown on the 3D label; keep ≤ 16 chars where possible), `sub` is the address from content/inside-the-network.json or a short note like "Offline · no network", `title` is "NAME · address", `button` optional ≤ 16 chars.
- `scene.flows`: 0–6 animated paths between two nodes, shown at the listed 0-based lesson indexes (the "Course complete" view shows flows listed for the last lesson). `twoWay` animates both directions; `offline: true` draws a hand-carried media path (only for the offline root CA).
- `lessons`: one entry per lesson id in content/configuration-courses.json for your course, in any order.
  - `tag`: "NN / WORD" — two-digit lesson number and one or two UPPERCASE words (1.1: "01 / PREPARE", "02 / CONFIGURE", "04 / VERIFY").
  - `status`: what the 3D stage badge reads at this lesson, UPPERCASE (1.1: "PLANNED", "DC01 ONLINE", "TWO CONTROLLERS", "HEALTH CHECK").
  - `stepTitles`: exactly as many as the lesson has steps; ≤ 70 chars each; short imperative headings that name what the step does (1.1: "Prepare two separate VMs", "Record names and addresses").
  - `mistake`, `network`, control `body`/`question`: ≤ 700 chars each.
  - `checklist`: exactly 3 first-person observations the learner can tick after doing the lesson in their own lab (≤ 240 chars each).

## Check your file

Run `ONLY=<course id> node scripts/prepare-course-guides.mjs` from the repository root. It validates your file and writes public/training/<id>/index.html. Fix every error it reports. Then re-read your JSON against the lesson content once more for accuracy (names, addresses, which lesson configures what, control titles).

When done, reply with: the file path, the nodes and flows you chose (one line each), each lesson's control (ID + title), and anything in the lesson content you found inconsistent or were unsure about. Keep the reply short.
