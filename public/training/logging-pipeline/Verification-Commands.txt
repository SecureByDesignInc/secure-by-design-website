SECURE BY DESIGN - SEE EVERYTHING: THE LOGGING PIPELINE
Course 1.6 | Materials edition 1.4 | Updated 9 October 2026

Run each check in an elevated PowerShell session, or a shell on the Linux servers, on the host the lesson names.
Some lessons include the configuration commands they verify: read each command before you run it, and adapt
the example names, addresses, and paths to your own plan. Nothing in this file runs by itself.

1. Design collect, protect, analyze
# Capture the before state: what the DCs currently audit and where nothing is forwarded yet.
auditpol /get /category:* | Select-String 'Logon|Account Management|Directory Service|Policy Change'
Get-Service Wecsvc -ComputerName SBD-SYSLOG01

What success looks like: The design names each stage's job, scope, retention, and readers; the repository's no-delete rule is written; and the register carries the three pipeline paths with owners.

2. Turn on the right auditing
auditpol /get /subcategory:'Logon','User Account Management','Directory Service Changes','Audit Policy Change'
gpresult /r /scope:computer

What success looks like: Effective audit policy on the DCs and admin hosts covers the designed categories at or above the STIG values, applied through GPO, with any additions documented.

3. Build the collector
wecutil es
wecutil gs SBD-ForwardedSecurity
Get-WinEvent -LogName ForwardedEvents -MaxEvents 5 | Select-Object TimeCreated, Id, MachineName

What success looks like: The subscription is active, events from both DCs and the admin hosts appear in Forwarded Events with correct source machine names, and router deny entries arrive on the syslog intake.

4. Protect the record on SBD-AUDIT01
Get-ChildItem \\SBD-AUDIT01\LogArchive | Select-Object Name, Length, LastWriteTime -First 5
Get-FileHash -Algorithm SHA256 \\SBD-AUDIT01\LogArchive\*.evtx | Select-Object -First 3
icacls \\SBD-AUDIT01\LogArchive

What success looks like: Dated archives arrive on schedule with catalog hashes that verify, the permission listing matches the access model exactly, and the AU table reflects reality.

5. Analyze in SBD-SPLUNK01
Test-NetConnection SBD-SPLUNK01.sbd.test -Port 9997
# In the analysis console, confirm the three saved searches return today's events
Get-WinEvent -FilterHashtable @{LogName='Security';Id=4625} -MaxEvents 3 | Select-Object TimeCreated, MachineName

What success looks like: Both streams index with correct timestamps, the three searches return real current events, and the alert fires in a test with its responder and first step documented.

6. Prove the chain and delta scan
Get-WinEvent -FilterHashtable @{LogName='ForwardedEvents'; Id=4625; StartTime=(Get-Date).AddHours(-1)} | Select-Object TimeCreated, MachineName
Get-ChildItem C:\Evidence\logging-pipeline -Recurse | Select-Object Name, LastWriteTime
Get-FileHash -Algorithm SHA256 C:\Evidence\logging-pipeline\*

What success looks like: The test event appears at every stage with consistent timestamps, the deny trace matches, the new hosts have baselines, and the DC rescan deltas are attributed to the audit policy.
