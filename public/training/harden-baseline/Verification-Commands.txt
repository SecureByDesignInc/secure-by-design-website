SECURE BY DESIGN - HARDEN THE BASELINE
Course 1.3 | Materials edition 1.3 | Updated 9 October 2026

Run each check in an elevated PowerShell session, or a shell on the Linux servers, on the host the lesson names.
Some lessons include the configuration commands they verify: read each command before you run it, and adapt
the example names, addresses, and paths to your own plan. Nothing in this file runs by itself.

1. Design and build the OU structure
Get-ADOrganizationalUnit -Filter * | Select-Object Name, DistinguishedName
Get-ADDomain | Select-Object ComputersContainer, UsersContainer
(Get-ADOrganizationalUnit -Identity 'OU=SBD,DC=sbd,DC=test' -Properties ProtectedFromAccidentalDeletion).ProtectedFromAccidentalDeletion

What success looks like: The planned OUs exist with deletion protection, the default container redirects point at managed OUs, and each OU has a recorded purpose and administrator.

2. Stage the tooling across the air gap
Get-ChildItem C:\Staging\DISA | Select-Object Name, Length
Get-FileHash -Algorithm SHA256 C:\Staging\DISA\*

What success looks like: Every transferred file's hash matches the value recorded on the connected side, and tool and package versions are written down.

3. Capture the pre-hardening baseline
# Adapt paths to your SCC installation and session directory.
Get-ChildItem C:\Evidence\baseline -Recurse -Include *.xml | Select-Object Name, LastWriteTime
Get-FileHash -Algorithm SHA256 C:\Evidence\baseline\*

What success looks like: Both controllers have a dated baseline result set, the already-compliant OS defaults are noted, and the raw files are hashed and stored.

4. Import and link the DISA GPOs
Get-ChildItem \\sbd.test\SYSVOL\sbd.test\Policies\PolicyDefinitions | Measure-Object
Get-GPO -All | Select-Object DisplayName, GpoStatus, ModificationTime
Get-GPInheritance -Target 'OU=Domain Controllers,DC=sbd,DC=test'
gpupdate /force
gpresult /r /scope:computer

What success looks like: The central store serves the package's templates, the imported GPOs are linked to the intended OUs, gpresult shows them applying, and every deviation has a written reason.

5. Rescan, reconcile, and record
# Compare result sets; adapt paths to your evidence layout.
Get-ChildItem C:\Evidence\baseline, C:\Evidence\hardened -Recurse -Include *.xml | Select-Object Directory, Name
Get-FileHash -Algorithm SHA256 C:\Evidence\hardened\*
gpresult /h C:\Evidence\hardened\SBD-DC01-gpresult.html

What success looks like: Both hosts show the expected movement from the baseline, every change is attributable, and every open item is a finding, a deviation, or a POA&M candidate — never unexplained.

6. Set the rescan cadence and exception record
Get-GPOReport -All -ReportType Html -Path C:\Evidence\gpo-report.html
Backup-GPO -All -Path C:\Evidence\gpo-backup
Get-FileHash -Algorithm SHA256 C:\Evidence\gpo-report.html

What success looks like: The exception list has owners and review dates, the GPO set is exported and backed up, and the rescan triggers are written where the next course will meet them.
