Inside the Network

Read the network as text

The same air-gapped design as the 3D model: 8 VLANs, 22 systems (one is a pool of 50 Windows PCs; SBD-ROOTCA01 stays offline), 7 traffic processes, and 60 NIST SP 800-53 Revision 5 controls.

Systems 22

SBD-DC01

AD DS + DNS · VLAN 10 · Domain controllers · 10.0.10.10 · Virtual machine on SBD-HV01 · rack R02 · server room

Find services, authenticate identities, and answer directory requests.

  • DNS TCP / UDP 53
  • Kerberos KDC TCP / UDP 88 · Password changes use TCP / UDP 464.
  • Directory access LDAP TCP / UDP 389 · LDAPS TCP 636 · UDP 389 carries the domain controller locator ping. Client and protection settings determine the binding.
  • Global catalog TCP 3268 · TLS TCP 3269
  • Group Policy and SYSVOL SMB · TCP 445
  • RPC services TCP 135 · dynamic TCP 49152–65535 · NetLogon, LSA, and SAM use the dynamic range after the endpoint mapper.
  • Domain time W32Time · UDP 123 · Members follow the domain time hierarchy.
  • AD Web Services TCP 9389 · Used by Active Directory PowerShell and Administrative Center from the Tier 0 administration host (rule A01), not user workstations.
  • AC-2 Account Management

  • AC-6 Least Privilege
  • AU-8 Time Stamps
  • SC-45 System Time Synchronization

Follow the traffic 7 processes

01 · Sign in: A workstation finds its identity.

Addressing, name resolution, and domain authentication.

  1. Obtain a network address 50 Windows PCs → SBD-DHCP01 · DHCP · UDP 67 / 68

    A new client requests an address and receives lease settings. The exchange includes discovery, offer, request, and acknowledgement.

  2. Locate directory services 50 Windows PCs → SBD-DC01 · DNS · TCP / UDP 53

    The workstation asks internal DNS to locate domain services. DNS records connect service names to reachable hosts.

  3. Authenticate to the domain 50 Windows PCs → SBD-DC01 · Kerberos · TCP / UDP 88

    The client proves its identity to the domain controller’s Key Distribution Center and obtains a ticket-granting ticket.

  4. Read directory information 50 Windows PCs → SBD-DC01 · LDAP · TCP 389 / LDAPS · TCP 636

    The workstation reads its computer and policy objects from Active Directory, then fetches Group Policy from SYSVOL over SMB. Rule F03 permits the full directory profile for domain members.

02 · Open a file: From a name to an authorized file.

Follow a domain client to its file share.

  1. Resolve the file server 50 Windows PCs → SBD-DC01 · DNS · TCP / UDP 53

    The client resolves the file server’s name before opening a connection. The diagram uses SBD-FS01 as the named destination.

  2. Request a service ticket 50 Windows PCs → SBD-DC01 · Kerberos · TCP / UDP 88

    The workstation uses its ticket-granting ticket to request a ticket for the file service. It then presents that service ticket to the server.

  3. Open the approved share 50 Windows PCs → SBD-FS01 · SMB · TCP 445

    The client requests a file over SMB. The server applies the relevant share and filesystem permissions before allowing access.

03 · Get updates: Bring updates inside. Distribute with care.

A disconnected update workflow, with no internet edge.

  1. Import approved update material Authorized operator → SBD-WSUS01 · MANUAL TRANSFER · NO NETWORK SESSION

    An authorized operator brings approved update material across the air gap using controlled media and an established import process.

  2. Check update metadata 50 Windows PCs → SBD-WSUS01 · HTTPS · TCP 8531

    The client contacts the internal WSUS service for update metadata using the TLS-enabled configuration.

  3. Retrieve signed update content 50 Windows PCs → SBD-WSUS01 · HTTP · TCP 8530

    WSUS uses its HTTP connection for update payloads, with signatures protecting payload authenticity. TLS is used for metadata rather than every WSUS path.

04 · Follow a log: Turn an event into useful evidence.

From Windows and Linux sources to collection, analysis, and retention.

  1. Forward a domain controller event SBD-DC01 → SBD-SYSLOG01 · EVENT FORWARDING · WinRM TCP 5985

    SBD-DC01 pushes the subscribed security events to the collector. The collector never reaches into the source: the subscription is source-initiated, set by Group Policy.

  2. Deliver a source event SBD-REPO01 → SBD-SYSLOG01 · SYSLOG OVER TLS · TCP 6514

    A configured Linux source can initiate a protected syslog session to the collector. The connection uses TLS transport.

  3. Ingest for investigation SBD-SYSLOG01 → SBD-SPLUNK01 · SPLUNK FORWARDER · TCP 9997 + TLS

    The forwarder on the collector sends the Windows events and syslog intake to Splunk for indexing, searches, and alerts.

  4. Retain an audit copy SBD-SYSLOG01 → SBD-AUDIT01 · ARCHIVE · SMB 3 · TCP 445

    On schedule, the collector writes dated archive files to the repository share on SBD-AUDIT01. Each archive is hashed and cataloged on arrival.

05 · License check: A licensing service has its own contract.

Follow the client request to its licensing service.

  1. Request a license 50 Windows PCs → SBD-APPS01 · VENDOR LICENSING · REGISTERED PORT

    An approved client contacts the licensing service to check or obtain its entitlement. Protocol, direction, persistence, and offline behavior depend on the product.

06 · Offline trust: The root stays outside the live network.

A controlled offline certificate ceremony.

  1. Prepare the signing material Authorized operator → SBD-SUBCA01 · OFFLINE CEREMONY · NO LIVE PATH

    Prepare the subordinate CA’s signing request and the records required for the ceremony. Protect the request and validate the intended certificate policy.

  2. Use the offline root Authorized operator → SBD-ROOTCA01 · OFFLINE ROOT · NO NETWORK SESSION

    Authorized operators use the protected root key in a controlled ceremony. The root CA remains non-domain-joined and disconnected.

  3. Return publication artifacts Authorized operator → SBD-SUBCA01 · CONTROLLED TRANSFER · NO LIVE PATH

    Return approved certificate and revocation artifacts through the documented offline transfer process. Define the issuing CA’s enrollment and publication design separately.

07 · Use a web app: A browser trusts the internal web service.

Name resolution, certificate trust, revocation, and an encrypted session.

  1. Resolve the web server 50 Windows PCs → SBD-DC01 · DNS · TCP / UDP 53

    The browser resolves the web service’s internal name before connecting. DNS returns SBD-WEB01’s address on VLAN 40.

  2. Verify the server certificate 50 Windows PCs → SBD-WEB01 · HTTPS · TCP 443

    The browser opens a TLS session. SBD-WEB01 presents a certificate from the internal issuing CA, and the client checks the name, validity dates, and chain to the trusted offline root.

  3. Check revocation 50 Windows PCs → SBD-PKI-MGMT01 · CRL / AIA · HTTP TCP 80

    The client follows the CRL distribution point in the certificate to pki.sbd.test on SBD-PKI-MGMT01 and downloads the issuing CA’s current revocation list.

  4. Request the application 50 Windows PCs → SBD-WEB01 · HTTPS · TCP 443

    Inside the encrypted session, the browser sends HTTP requests and receives the application’s responses. The application decides what the signed-in user may see.

What if… 5 scenarios

DC01 is down: One domain controller fails.

The client turns to SBD-DC02 for DNS and authentication.

  1. Query SBD-DC01 50 Windows PCs → SBD-DC01 · DNS · TCP / UDP 53

    The workstation sends its DNS query to its first configured DNS server. SBD-DC01 is offline, so no reply comes back.

  2. Retry with SBD-DC02 50 Windows PCs → SBD-DC02 · DNS · TCP / UDP 53

    The client retries with its next configured DNS server. SBD-DC02 also provides DNS for the domain and answers.

  3. Authenticate with SBD-DC02 50 Windows PCs → SBD-DC02 · Kerberos · TCP / UDP 88

    DNS service records list both domain controllers, and the client’s domain controller locator finds SBD-DC02 responding. SBD-DC02’s Key Distribution Center issues the ticket-granting ticket.

Certificate expired: The browser refuses an expired certificate.

Trust checks fail before any application data is sent.

  1. Resolve the web server 50 Windows PCs → SBD-DC01 · DNS · TCP / UDP 53

    The browser resolves the web service’s internal name, exactly as on a normal day.

  2. Present an expired certificate 50 Windows PCs → SBD-WEB01 · HTTPS · TCP 443

    SBD-WEB01 presents a certificate whose validity period has ended. The browser checks the dates, stops the connection, and shows a certificate error.

A PC tries SQL: Default deny stops a direct database connection.

No exception exists for workstation-to-SQL traffic.

  1. Connect straight to SBD-SQL01 50 Windows PCs → SBD-SQL01 · SQL · TCP 1433

    A workstation tries to reach the database server directly. The core finds no matching exception, so default deny drops the session.

PC-to-PC remote desktop: Host firewalls stop lateral movement.

One workstation tries remote desktop to another.

  1. Open remote desktop to another PC 50 Windows PCs → 50 Windows PCs · RDP · TCP / UDP 3389

    A workstation tries a remote desktop session to a peer on the same VLAN. The destination’s host firewall refuses it.

Attack drill: An intruder tests every boundary.

Six moves an intruder might try, from one compromised PC to a stolen admin session. Each is checked against the rules.

  1. A compromised PC tries the database 50 Windows PCs → SBD-SQL01 · SQL · TCP 1433

    Malware on one workstation reaches straight for SBD-SQL01. No exception exists for workstation-to-SQL traffic, so the core drops the attempt.

    Acceptance test: Client-to-SQL, client-to-management, and peer SMB/RDP fail.

  2. It looks for the security tools 50 Windows PCs → SBD-SPLUNK01 · MANAGEMENT · Splunk Web · TCP 8000

    Taking over a security tool would blind the defenders. The PC tries Splunk’s web interface. No rule lets user workstations reach security-tool management, so default deny drops it.

    Acceptance test: A compromised client cannot reach security-tool management interfaces.

  3. It tries a neighbor’s file shares 50 Windows PCs → 50 Windows PCs · SMB · TCP 445

    Next, the PC tries the shares on another workstation in VLAN 80. The traffic never crosses the core, so the neighbor’s host firewall refuses it.

    Acceptance test: Client-to-SQL, client-to-management, and peer SMB/RDP fail.

  4. It tries remote desktop to a neighbor 50 Windows PCs → 50 Windows PCs · RDP · TCP / UDP 3389

    The PC tries a remote desktop session to a peer. The destination’s host firewall refuses it.

    Acceptance test: Client-to-SQL, client-to-management, and peer SMB/RDP fail.

  5. A compromised web server reaches for the database SBD-WEB01 → SBD-SQL01 · SQL · TCP 1433

    If SBD-WEB01 were taken over, SBD-SQL01 would be the next target. They share VLAN 40, so the core never sees this traffic. SBD-SQL01’s host firewall refuses it.

    Acceptance test: The web server cannot reach SQL directly; only SBD-APPS01, the registered consumer, connects.

  6. A stolen admin session aims at a domain controller SBD-ADMIN-PC01 → SBD-DC01 · MANAGEMENT · REMOTE ADMINISTRATION

    With an endpoint administrator’s stolen session on SBD-ADMIN-PC01, the attacker aims at SBD-DC01. That host manages user endpoints only. No rule lets it manage a domain controller, so default deny drops it.

    Acceptance test: An endpoint administrator cannot manage a DC, issuing CA, or member server.
