Bring in the fleet

Join the fifty-workstation fleet to a network that is ready for it: DHCP addressing, OU landing with STIG policy at first boot, Windows LAPS for every local administrator, certificate autoenrollment at scale, and a sampled proof with the whole rollout observed by the logging pipeline.

7 lessons · ~3.2h · Self-paced · Written edition

Before you start · prerequisites and lab plan
  • Complete courses 1.4–1.6: working PKI services, DHCP with its relay, the tiered admin plane, and the logging pipeline, on the network's routed, segmented VLANs.
  • Prepare a patched Windows reference image (or template) for the fifty endpoints, obtained through the approved offline media process.
  • Confirm the Workstations OU, the container redirects from course 1.3, and the Defense Information Systems Agency (DISA) Security Technical Implementation Guide (STIG) Group Policy objects (GPOs) for your Windows client release, from the course 1.3 package, are ready to link.
  • Confirm the VLAN 80 access switch supports 802.1X port authentication, including a monitor (audit) mode that logs each result without blocking traffic. No new server is needed: the Network Policy Server (NPS) role goes on SBD-DHCP01.

Fifty endpoints join a network that is finally ready for them: addressed by DHCP, landed by OU redirect, hardened by policy at first boot, certified by autoenrollment, and watched by the pipeline from their first sign-in. The sample names run SBD-PC01 through SBD-PC50; match them to your own plan.

YOUR LEARNING PATH

LESSON 1 OF 7 · ABOUT 30 MIN

Prepare the fleet rollout

Fifty of anything needs a factory, not fifty craft projects. Settle the image, the names, the join account, and the policy links so every endpoint is born identical — then prove it on paper before proving it on metal.

In this lesson you will

  • Finalize the reference image and naming plan for fifty endpoints.
  • Create a least-privilege join account scoped to the Workstations OU.
  • Link the Windows client STIG policies and the workstation firewall policy to the Workstations OU before any join.

Work through the configuration

  1. Finalize the Windows reference image: current patches via the approved media process, no preinstalled extras, and a generalized state so each clone takes its own identity. Record the image version and hash — it is the fleet's common ancestor and belongs in evidence.
  2. Write the naming and rollout plan: SBD-PC01–SBD-PC50, addressed by the course 1.5 DHCP scope, joined in waves (pilot of three, then batches) rather than all fifty at once.
  3. Create a dedicated domain-join account delegated only the create-computer-objects right on the Workstations OU — no broader privilege rides along with fifty join operations. The course 1.3 redirect already guarantees machines land in that OU.
  4. Link the DISA Windows client STIG policies from the course 1.3 package to the Workstations OU now, so the very first pilot boots into the hardened state — and note that the Windows client's own secure defaults will already satisfy some checks, just as Windows Server's did.
  5. Create the workstation firewall GPO (SBD Workstation Firewall in this sample) on the Workstations OU: Windows Defender Firewall on for every profile with inbound traffic blocked by default, and inbound rules that allow SMB (TCP 445), Remote Desktop (TCP 3389), and remote management (TCP 5985–5986) only from SBD-ADMIN-PC01 at 10.0.60.30 — course 1.8 adds SBD-NESSUS01 for credentialed scans. No rule allows SMB or Remote Desktop between workstations: traffic inside VLAN 80 never reaches the router, so this policy, not the core router's rules, enforces the register's peer denies.

Inspect your configuration

Run the relevant checks in an elevated PowerShell session — or a shell, on the Linux servers — on the host identified in the lesson. Adapt the example names and paths to your lab.

Get-FileHash -Algorithm SHA256 C:\Staging\Win11-Reference.vhdx
Get-ADOrganizationalUnit -Identity 'OU=Workstations,OU=SBD,DC=sbd,DC=test'
Get-GPInheritance -Target 'OU=Workstations,OU=SBD,DC=sbd,DC=test'
Get-GPOReport -Name 'SBD Workstation Firewall' -ReportType Html -Path C:\Evidence\workstation-fleet\workstation-firewall.html

What success looks like

The image is hashed and recorded, the join account holds only the delegated right on the Workstations OU, and the STIG and firewall GPO links show on that OU before any machine exists in it.

Keep your evidence

Keep the image record with its hash, the naming and wave plan, the delegation report for the join account, the OU's GPO inheritance output, and the firewall GPO report.

Lesson recap

  • One hashed image, one naming plan, waves instead of a big bang.
  • The join credential can create computer objects and nothing else.
  • The Workstations OU is armed with policy before it holds a machine.
  • Peer SMB and Remote Desktop are blocked by each PC's own firewall, set by policy before the first join.
