Configure DNS and time

YOUR LEARNING PATH

LESSON 1 OF 6 · ABOUT 25 MIN

Map names to the network

Domain Name System (DNS) turns names into addresses, and for Active Directory it does one more job: it tells every domain member where its domain controllers are. Start from the working directory build, learn what DNS answers and what it doesn't, set each controller's DNS client order, and record which server owns each name and how a client finds it.

In this lesson you will

  • Explain how DNS lets a domain member find a domain controller, and what a DNS answer does not prove.
  • Set each domain controller's DNS client order and point domain members only at internal DNS.
  • Inventory the existing sbd.test and _msdcs zones without creating duplicates.
  • Document the forwarding and recursion decision for an air-gapped network.

Work through the configuration

  1. Start with what DNS answers. An A record maps a host name to an IPv4 address (AAAA maps to IPv6), so SBD-DC01.sbd.test resolves to 10.0.10.10. Service (SRV) records advertise which servers offer a service: a domain member asks for _ldap._tcp.dc._msdcs.sbd.test, resolves a listed controller's name, contacts it, and only then authenticates. DNS never checks a password, and it works on an isolated network with no internet access.
  2. Record the domain, each subnet, both DNS addresses, and the owner of each service name. Keep host records and service aliases distinguishable.
  3. On each domain controller, confirm the DNS Server service is installed and running; an address typed into a network adapter installs nothing. Then open DNS Manager and review the sbd.test and _msdcs.sbd.test zones that promotion created, without creating duplicates. The DNS delegation warning from course 1.1's promotion is expected: no parent zone exists above the isolated .test namespace, so no action is needed.
  4. Set each controller's DNS client order. Promotion pointed SBD-DC01 at itself (the loopback address, 127.0.0.1) while it was the only controller, and SBD-DC02 pointed at SBD-DC01 so it could find the domain. Run the replication summary first; once replication succeeds in both directions, list the partner controller first and the loopback address second on each, and never an outside resolver. Domain members list both controllers; a public resolver is not an alternate for this environment.
  5. Confirm the network's service-path register permits DNS: every networked system to both domain controllers on TCP and UDP 53 (rule F01 in Inside the Network). A member has to find a controller before any Kerberos, LDAP, or Group Policy traffic can start.
  6. Decide whether any separate internal namespace needs a conditional forwarder. With no recursive dependencies, document a no-recursion design; do not add internet forwarders or delete every root hint as a shortcut.

Inspect your configuration

Run the relevant checks in an elevated PowerShell session — or a shell, on the Linux servers — on the host identified in the lesson. Adapt the example names and paths to your lab.

Invoke-Command SBD-DC01,SBD-DC02 { Get-WindowsFeature DNS; Get-Service DNS }
repadmin /replsummary
Get-DnsClientServerAddress -AddressFamily IPv4 -CimSession SBD-DC01,SBD-DC02
# After replication succeeds both ways (adapter name varies):
Set-DnsClientServerAddress -CimSession SBD-DC01 -InterfaceAlias Ethernet `
  -ServerAddresses 10.0.10.11,127.0.0.1
Set-DnsClientServerAddress -CimSession SBD-DC02 -InterfaceAlias Ethernet `
  -ServerAddresses 10.0.10.10,127.0.0.1
Get-DnsClientServerAddress -AddressFamily IPv4 -CimSession SBD-DC01,SBD-DC02
Get-DnsServerZone -ComputerName SBD-DC01

What success looks like

Both controllers run the DNS Server service and, once replication succeeds both ways, list their partner first and the loopback address second. Members list both controllers only; the AD zones, the recursion decision, and the register rows that permit DNS are recorded.

Keep your evidence

Save the address/name worksheet, each controller's DNS client order and the reason for it, and the initial zone inventory before changing anything else.

Lesson recap

  • DNS finds domain controllers through SRV records; it never checks a password.
  • Each controller lists its partner, then itself; members list both controllers only.
  • The AD zones are inventoried, not recreated, and the delegation warning is expected.
  • The forwarding and recursion decision is written down first.
