Patch, protect, and watch for weakness

Keep the proven state from drifting: Windows updates through WSUS rings fed across the air gap, one approved source per software type with SBD-REPO01 for packages, a living inventory on SBD-MGMT01, managed endpoint protection through SBD-EPO01, and SBD-NESSUS01 turning the scan cadence into routine.

Before you start · prerequisites and lab plan
  • Complete course 1.7: the fleet exists, inventoried and reporting into the logging pipeline.
  • Provision SBD-WSUS01 (10.0.20.30), SBD-REPO01 (10.0.70.20, Linux), SBD-MGMT01 (10.0.70.10), SBD-EPO01 (10.0.50.30), and SBD-NESSUS01 (10.0.50.20) per the model's placements.
  • Keep the approved-media process ready: update content, package mirrors, protection definitions, and scanner plugins all cross the air gap the same reviewed, hashed way.

This course keeps the proven state from drifting: updates and software arrive only through controlled channels, every endpoint runs managed protection, and a credentialed scanner turns the course 1.3 cadence into routine. In an air-gapped lab, every one of these systems feeds on content carried across the boundary — which is the recurring lesson.

YOUR LEARNING PATH

LESSON 1 OF 6 · ABOUT 20 MIN

Design the rings and the software rules

Decide how change reaches the network before any of it does: update rings that try things on the expendable before the essential, one approved source per software type, and register rows for every new path.

In this lesson you will

  • Define the update rings and their order.
  • Set the one-approved-source rule per software type.
  • Register the course's service paths.

Work through the configuration

  1. Define three rings and their order: a pilot ring (the course 1.7 sample machines plus one member server), the broad ring (fleet and member servers), and the critical ring last (domain controllers and both VLAN 30 hosts) — updates earn their way up, never down.
  2. Write the software rule: Windows updates come only from SBD-WSUS01, Linux packages only from SBD-REPO01, protection definitions only through SBD-EPO01, and anything else arrives as a documented exception — one source per type is what makes 'unauthorized software' a checkable claim.
  3. Decide the air-gap feeding cadence: what content crosses on media, how often, hashed by whom — the course 1.3 transfer procedure, now on a schedule.
  4. Add the register rows: every Windows system to WSUS (8530/8531), domain controllers included; the domain-joined Linux servers (SBD-SPLUNK01 and SBD-NESSUS01) to REPO01 (HTTP, GPG-signed packages); every Windows system's agent to Trellix ePolicy Orchestrator (ePO) on SBD-EPO01 on its agent-server secure port, TCP 443, with the agent starting each connection; and the scanner's credentialed reach into each VLAN (SMB 445 and WMI to Windows, SSH 22 to Linux) — the one deliberate wide permit, owned and logged.

Inspect your configuration

Run the relevant checks in an elevated PowerShell session — or a shell, on the Linux servers — on the host identified in the lesson. Adapt the example names and paths to your lab.

# Capture the before state: where machines currently look for updates (nowhere internal yet).
Get-ItemProperty 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate' -ErrorAction SilentlyContinue
Get-ADComputer -Filter * -SearchBase 'OU=SBD,DC=sbd,DC=test' | Measure-Object

What success looks like

The ring table names every system's ring, the one-source rule and feeding cadence are written, and the register carries the course's rows with owners.

Keep your evidence

Keep the ring assignments, the software source rules, the feeding cadence, and the new register rows.
