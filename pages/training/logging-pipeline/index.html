Before you start · prerequisites and lab plan
  • Complete course 1.5: the admin plane exists, and this course's systems are managed only from VLAN 60.
  • Provision SBD-SYSLOG01 (10.0.20.20) as Windows Server, SBD-SPLUNK01 (10.0.50.10) on Linux joined to the sbd.test domain with its time service (chrony or ntpd) pointed at both domain controllers, and SBD-AUDIT01 (10.0.50.40) as Windows Server joined to the domain.
  • Have the network's service-path register ready for the new rows: event forwarding to the collector, syslog from the core router, and the forwarder path into the analysis system.

This course builds the model's collect → protect → analyze chain before the fleet arrives, so every later system is observed from its first boot. Collection is configuration you can show; protection is permissions and retention you can defend; analysis is a search someone actually runs.

YOUR LEARNING PATH

LESSON 1 OF 6 · ABOUT 20 MIN

Design collect, protect, analyze

Three systems, three distinct jobs: SBD-SYSLOG01 gathers, SBD-AUDIT01 preserves, SBD-SPLUNK01 answers questions. Decide what is collected first, how long it lives, and who may touch which stage — before a single event flows.

In this lesson you will

  • Assign the three roles and the first collection scope.
  • Decide retention, protection, and access per stage.
  • Register the pipeline's network paths.

Work through the configuration

  1. Write the role sentence for each host: the collector receives Windows events and the core router's syslog; the repository holds the protected, long-retention copy; the analysis system indexes a working copy for search and alerting. One copy to keep, one copy to question.
  2. Scope the first collection to what already produces evidence: both DCs' Security logs, the core router's deny log, and the admin hosts' sign-in events — the fleet joins this scope in the next course, not now.
  3. Decide the AU-family answers and write them down: retention length per stage, who may read each stage, and that nobody — including administrators — writes or deletes in the repository outside the archival process (that is the AU-9 protection story).
  4. Add the register rows: DC and admin-host event forwarding to the collector (WinRM 5985), router syslog UDP 514 to the collector, and the forwarder path from collector to the analysis system; all three systems are managed only from VLAN 60 per course 1.5's handoff.

Inspect your configuration

Run the relevant checks in an elevated PowerShell session — or a shell, on the Linux servers — on the host identified in the lesson. Adapt the example names and paths to your lab.

# Capture the before state: what the DCs currently audit and where nothing is forwarded yet.
auditpol /get /category:* | Select-String 'Logon|Account Management|Directory Service|Policy Change'
Get-Service Wecsvc -ComputerName SBD-SYSLOG01

What success looks like

The design names each stage's job, scope, retention, and readers; the repository's no-delete rule is written; and the register carries the three pipeline paths with owners.

Keep your evidence

Keep the pipeline design sheet, the retention and access table, and the new register rows.
