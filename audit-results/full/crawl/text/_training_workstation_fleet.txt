In this lesson you willFinalize the reference image and naming plan for fifty endpoints.Create a least-privilege join account scoped to the Workstations OU.Link the Windows 11 STIG policies and the workstation firewall policy to the Workstations OU before any join.Work through the configurationFinalize the Windows 11 reference image: current patches via the approved media process, no preinstalled extras, and a generalized state so each clone takes its own identity.
Record the image version and hash — it is the fleet's common ancestor and belongs in evidence.Write the naming and rollout plan: SBD-PC01–SBD-PC50, addressed by the course 1.7 DHCP scope, joined in waves (pilot of three, then batches) rather than all fifty at once.Create a dedicated domain-join account delegated only the create-computer-objects right on the Workstations OU — no broader privilege rides along with fifty join operations.
The course 1.3 redirect already guarantees machines land in that OU.Link the DISA Windows 11 STIG policies from the course 1.3 package to the Workstations OU now, so the very first pilot boots into the hardened state — and note that Windows 11's own secure defaults will already satisfy some checks, just as Server 2025 did.Create the workstation firewall GPO (SBD Workstation Firewall in this sample) on the Workstations OU: Windows Defender Firewall on for every profile with inbound traffic blocked by default, and inbound rules that allow SMB (TCP 445), Remote Desktop (TCP 3389), and remote management (TCP 5985–5986) only from SBD-ADMIN-PC01 at 10.0.60.30 — course 1.10 adds SBD-NESSUS01 for credentialed scans.
No rule allows SMB or Remote Desktop between workstations: traffic inside VLAN 80 never reaches the router, so this policy, not the course 1.5 router rules, enforces the register's peer denies.Inspect your configurationRun the relevant checks in an elevated PowerShell session — or a shell, on the Linux servers — on the host identified in the lesson.
