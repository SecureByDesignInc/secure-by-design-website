In this lesson you willWrite the register rows for every business service path.Choose managed service identities instead of password accounts.Define the access groups that will own each service's data.Work through the configurationWrite the service-path rows: fleet to FS01 (SMB 445); fleet to APPS01 on its licensing port, recorded per application; fleet to WEB01 (HTTPS 443); WEB01 to APPS01 for the application API (HTTPS 443); and APPS01 — and only APPS01 — to SQL01 (TCP 1433 with TLS).
Add an explicit deny from WEB01 to SQL01: the web tier has no database dependency.
All four servers share VLAN 40, so the router never sees their traffic to each other — each server's host firewall enforces those rows.
Everything else toward VLAN 40 stays denied, including endpoint-to-SQL directly.Register WEB01's Linux maintenance rows as well: packages from SBD-REPO01 only (HTTP with GPG-signed packages) and syslog over TLS to the collector, SBD-SYSLOG01 (TCP 6514) — the same paths the other domain-joined Linux servers, SBD-SPLUNK01 and SBD-NESSUS01, use.
Course 1.10's repository row named only those two because WEB01 did not exist yet.Choose the service identities: group managed service accounts (gMSAs) for the SQL and application services, so passwords rotate themselves — and note Windows Server 2025's delegated managed service accounts as the migration path for any legacy service account this lab later inherits.Create the access groups under the course 1.3 Groups OU — per-share and per-application role groups — because permissions will be granted to roles, never to named humans.Request the server certificates through the course 1.6 process: one SBD Server Authentication certificate each for SQL01, APPS01 (for its application API), and WEB01, enrolled from the template, with the publication site serving their revocation story.Inspect your configurationRun the relevant checks in an elevated PowerShell session — or a shell, on the Linux servers — on the host identified in the lesson.
