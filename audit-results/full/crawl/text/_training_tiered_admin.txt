Write that policy against the OU structure, then plan the DHCP scope the fleet will live in — both before any host is built.
In this lesson you willDefine the tiers and map each to systems, OUs, and admin accounts.Write the credential rule each tier enforces.Plan the VLAN 80 DHCP scope, options, and relay.Work through the configurationDefine three tiers against what exists, using Microsoft's rule: anything that can control a Tier 0 system is Tier 0.
Tier 0 is the identity and trust fabric (DCs, both CAs, PKI-MGMT01) plus what controls it — the hypervisor hosts and their console, the core router's management, and the DC-facing parts of the tools that patch, protect, scan, monitor, and back up the DCs.
Tier 1 is the member servers; Tier 2 the user endpoints.
Map each tier to its OUs: Tier 0 to the Domain Controllers OU plus a new Tier 0 Servers OU for SBD-SUBCA01 and SBD-PKI-MGMT01 (lesson 4 moves them out of the Servers OU), Tier 1 to the Servers OU, and Tier 2 to the Workstations OU.Write the credential rule per tier: a Tier 0 account signs in only on Tier 0 systems and AdminJumpBox01; Tier 1 admins work from SBD-ADMIN-SRV01; Tier 2 from SBD-ADMIN-PC01.
The audit custodian uses separate accounts and sessions on SBD-ADMIN-SRV01 that ordinary server operators cannot use.
Each administrator gets separate per-tier accounts — the daily account holds no admin rights anywhere.Plan the DHCP design: scope 10.0.80.100–199 for the workstation VLAN — 100 addresses, room for the 50 PCs, the test clients, and replacement machines whose old leases have not yet expired — with options for router 10.0.80.1, the two DCs as DNS, and the sbd.test domain; the core router relays VLAN 80 broadcasts to SBD-DHCP01; everything else stays static.Add the register rows this course needs: VLAN 60 to each tier's management ports (rules A01–A04 in Inside the Network), DHCP relay from the core to SBD-DHCP01 (F04), and explicit denies from VLAN 80 into VLAN 60 — user space never initiates toward the admin plane.Inspect your configurationRun the relevant checks in an elevated PowerShell session — or a shell, on the Linux servers — on the host identified in the lesson.
